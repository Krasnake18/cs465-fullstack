During the Travlr Getaways project we had the opportunity to work with different front-end development approaches, including Express HTML, JavaScript, and an Angular single-page application (SPA).  Express HTML allowed us to display the customer-facing website, JavaScript allowed for the interactive features and functionality.  The Angular SPA allowed for a more dynamic administrative interface and allowed for updates without needing to perform a full page reload.  Angular allowed us to use reusable parts that allowed us to make the application easier to organize.  On the backend, we used MongoDB due to the document-based structure providing flexibility for storing travel information.  MongoDB stores data in JSON documents making it compatible with JavaScript that was used.  Using architecture like this lets the front end, backend, and database communicate efficiently while supporting both customer and administrative functionality.
JSON and JavaScript were both used in our full stack development.  JavaScript, a programming language, was used to implement application functionality.  JSON is a format that is used to exchange data between systems.  In our Travlr Getaways application JSON allowed us to connect the frontend and the backend which allowed for application to be able to send and receive travel information through API requests.  While working on the project we worked on refactoring many areas of application to improve both the functionality and the efficiency.  We also improved routing, trip editing functionality, and authentication-related controls during development.  By using UI components that can be reused we were able to reduce duplicate code, improved consistency, and made troubleshooting easier because individual components could be updated without requiring major changes throughout the application.
We performed testing since it has a major role in developing Travlr Getaways because the application required communication between the frontend, backend, and MongoDB database.  We learned how the API endpoints use HTTP methods like GET to get information, POST to create records, PUT to update records, and Delete to remove records.  By testing these endpoints, we were able to make sure that requests were performed correctly and that changes were reflected.  We also added authentication, which created additional challenges due to the administrate functions needing to be restricted to only authorized users.  We also made sure that the administrative controls were visible based on the login status, and we made sure that users could log out successfully.   This experience reinforced the importance of testing both successful operations and error conditions to maintain application functionality and security.
